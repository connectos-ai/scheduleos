# Code of Conduct

ScheduleOS should be a respectful, practical, and safety-minded open-source project.

## Expected Behavior

- Be kind, direct, and constructive.
- Assume good intent while still naming risks clearly.
- Respect privacy and never request or share private data unnecessarily.
- Keep discussions focused on making scheduling, calendar, and task-planning software more useful and trustworthy.
- Credit prior art and third-party work accurately.

## Unacceptable Behavior

- Harassment, threats, hate speech, or personal attacks.
- Sharing private data, secrets, credentials, or customer information.
- Pressuring maintainers to weaken security, privacy, licensing, or release gates.
- Misrepresenting ScheduleOS as a production-ready public release before the documented gates pass.

## Enforcement

Before public release, maintainers should handle incidents privately and document any required project changes. When the public repository is created, this file should be updated with project-specific reporting contacts and enforcement procedures.
